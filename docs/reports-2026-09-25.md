# September issue fixes and validation

Work branch: `fix/september-reports`. Scope: #56, #57, #61, #62, #63;
Android (#59) excluded. This is local validation, not a release sign-off.

## Confirmed fixes

- #61: the volume menu cached its packet cursor before drawing the cursor
  arrow. Labels overwrote arrow packets and inherited the volume bars' texture
  page. Allocate labels after the arrow and explicitly select their text page.
  A packet regression failed before the fix; a rendered-image test checks all
  three labels and both volume bars through the normal menu navigation.
- #63: newly inserted lap and total records use the team name, including the
  name editor's initial character. Tests cover empty, short, long and malformed
  encoded names and both record tables.

## Lighting and GPU work (#56, #57)

Headlights require 0.6 seconds of continuous darkness. Tail lights remain
visible at low intensity during daylight. Shadowed surfaces have a higher
minimum brightness and softened edges. Fully fogged/unlit fragments skip
unnecessary shadow rays; spot lights outside each camera's view are culled.
A valid traced sun shadow skips the redundant 4096-square depth shadow pass.

The shared vertex buffer previously reserved 112,000,000 bytes immediately,
although resident meshes hold most geometry separately. It now starts at
64 KiB and grows as needed, retaining the original maximum. All main/mirror
bindings are updated when it grows, and the resident prefix is republished.
The frozen scene needed 512 KiB; a two-race run peaked at 4 MiB. These numbers
refer only to the shared vertex buffer, not total GPU memory.

Fixed-scene macOS offscreen benchmark, PAL, class 4, car 3/variant 4,
track point 150, 1280x720, full tracing, 1,106 frame intervals:

| Build | Median interval | p95 |
|---|---:|---:|
| Before lighting/performance changes | 5.115 ms | 7.636 ms |
| After | 4.368 ms | 7.123 ms |

This is about 14.6% lower median interval locally, not a Radeon FPS claim.
The buffer allocation change produced a byte-identical fixed-scene capture.
An injected GPU submission failure rebuilt resources and subsequently produced
that same image. Two consecutive automated races with RT off completed on
macOS and Linux; this exercises mode/asset transitions, not manual driving.

Windows software-Vulkan testing exposed a separate, reproducible bug: with
RT off, the fragment shaders still declared four storage buffers but the
renderer did not bind them. The debugger caught a null access in SwiftShader
at the first native scene. The older 112 MB allocation crashed identically.
Initialize and bind minimum-sized resources even when tracing is disabled;
the uniforms still prevent tracing and no scene acceleration structure is
built. This also covers frames before a successful ray-scene upload.

## Pegase (#62): not reproduced

Real `LoadRaceAssets` integration tests now load a cars.toml override for both
Pegase grades through both GP series. AT overrides and shift thresholds apply,
and the retail source specification remains unchanged. The two grades have
different original thresholds. We still need the reporter's selected grade,
profile and save to reproduce the claimed Extra GP versus Time Attack difference.

Original MT-only defaults remain unchanged, following the prior project choice.
Whether to enable AT by default for those cars is a separate product decision.

## Platform validation

Release builds and unit/functional suites:

| Platform | Passed | Skipped | Failed |
|---|---:|---:|---:|
| macOS | 432 | 1 | 0 |
| Linux, darwine | 431 | 1 | 0 |
| Windows, ClangCL VM on darwine | 430 | 2 | 0 |

`render_stage_angles` lacks its prebuilt fixture on all three; Windows also
lacks the CUE required by `stream_table`. Both rendered-image tests
`volume_view` and `native_vertex_budget` pass on macOS and Linux.
After the storage-binding fix, both native/resident and expanded-CPU geometry
variants of `native_vertex_budget` also pass on Windows/SwiftShader with RT
off. The captured Windows frame was visually checked for car, track and HUD.
Before the fix the same test crashed; keeping the old vertex-buffer allocation
did not prevent that crash. Full-RT macOS output remains byte-identical.

The Windows VM uses Edge SwiftShader rather than a physical GPU. Its results
cannot verify the AMD driver's behavior or Radeon performance. The exact
second-race corruption/crash in #57 has not yet been reproduced on the tester's
hardware; the memory reduction alone is not proof of its resolution.
